# 学习通作业 · 执行手册（Playwright MCP 版）

> 2026-10-18 晚改用 `@playwright/mcp` 跑通《食品营养》96 题（91 客观 + 5 文本），取代旧 `mcp__browser` 方案。**本手册只描述 Playwright 这条正路，命令级步骤照第 3 节一步步做。**

## 0. 工具能力边界（为什么换 Playwright）

旧 `mcp__browser` 只有四类动作（读 DOM / 按 node_id 点 / 模拟键盘 / 截图），**没有 `execute_script`** → 1 题 = 1 次调用，96 题要 200 次，必然漏、必然慢。

Playwright MCP 补上了缺失的三块：

| 能力 | mcp__browser（旧，已弃用） | Playwright MCP（新，正路） |
|---|---|---|
| 执行 JS | ❌ 无 | ✅ `browser_evaluate`（页面上下文，读题+填答案主力） |
| 批量填题 | 1 题 = 1 次调用 | ✅ 一次 JS 循环改完全部 |
| 登录态 | 每次扫码 | ✅ `--user-data-dir` 固定 profile，登一次长期有效 |
| 进程存活 | Bash 起 4 秒被回收 | ✅ MCP server 常驻，不受 Job Object 回收 |

**四个主力工具**：`browser_navigate`（导航）／ `browser_snapshot`（读 accessibility 结构，比截图可靠）／ `browser_evaluate`（页面里跑 JS，读题+填答案）／ `browser_take_screenshot`（验收，**`scale` 必填**）。

## 1. 三条不做（沿用）

| 不做 | 原因 |
|---|---|
| ❌ 替他登录（扫码 / 密码） | 凭据不出他的手 |
| ❌ 替他点「提交」 | 提交权是他的；也是唯一能证明"本人在做"的环节 |
| ❌ 思政 / 价值观论述题给成文 | 只给思路 |

## 3. 命令级流程

### 3.1 打开 + 登录态

```
browser_navigate("https://i.chaoxing.com")
```

- `--user-data-dir=C:\Users\<你的用户名>\.pw_mcp_profile` 保留了登录态 → 直接进「个人空间」。
- 若跳到 `passport2.chaoxing.com` 登录页 → **停手叫他扫码**，登完再继续。
- **换账号**：先 `browser_navigate("https://passport2.chaoxing.com/logout")`，再回 `i.chaoxing.com`。⚠️ 账号是谁、要不要留登录态，他说了算。

### 3.2 读课程列表 + 问他要做哪门（每次必做，别默认）

```
登录/进个人空间后 → browser_snapshot（或 browser_evaluate）读「我的课程」列表
→ 把课名逐条报给他
→ 问他「这次做哪门课、写哪份作业」
```

- ⚠️ **不要默认去做上次的课**（哪怕同账号、同一份试卷）。每次都要问。
- 从课程列表里拿到该课的 URL（`mooc1.chaoxing.com/visit/stucoursemiddle?courseid=...`），留给下一步跳转。

### 3.3 点进课程 + 找未交作业 + 进作答页（我来点）

```
① 进课程：browser_navigate(该课 stucoursemiddle URL)，或 click 课程名 link
② 点「作业」：browser_click(getByRole('link', {name:'作业'}))
③ 作业列表：只点状态含「未交」的那份
④ 点作业 link 会开新 tab（N = dowork 作答页）→ browser_tabs(action:"select", index:N) 切过去
```

- **点课程用 URL 直跳最稳**，避免点错课（2026-10-18 想开「食品营养」、实际点开「单片机原理」）。
- ⚠️ **点作业链接会开新 tab**：切过去用 `browser_tabs(select)`；**不要又 `browser_navigate` 到 dowork URL**，会开两个作答页（2026-10-18 样点出）。
- 作业列表只做「未交」；「待批阅 / 已交 / 已完成」跳过。

### 3.4 读题

```
browser_evaluate(function:"() => { /* 抓所有题干 + 选项 + 填空位，return 结构化数据 */ }")
```

- **优先 `browser_evaluate` 直接抓 DOM**，一次拿全，别逐屏翻。
- 兜底用 `browser_snapshot` 读 accessibility tree（能看到 `<body contenteditable>` 真实内容，穿透 iframe）。
- 页面结构参考：`#submitForm > div`（大题型区块）→ `h2`（题型名）→ `div`（单题）→ `h3`（题干）→ `div[2] > div`（选项 / 填空位）。

## 4. 答案从哪来（核心：自动搜 + 生成 + 置信度标注）

**总原则**：水课作业 = 直接生成答案，**不设人工复核**（他 2026-10-18 定：查询类水课，我答了直接填；搜不到他自己也搜不到，单列复核无意义）。个别客观题可能错，属可接受。

### A · 他给了答案源（教材 / 习题册照片）—— 最优先

1. **先把答案逐条抄出来**，对话里原样列出，让他确认没漏读。
2. **按「屏幕上的题干」去答案里找对应**，不按题号硬对（学习通会重排题号）。
3. **章节号对不上 → 报一次**（差哪章 + 哪些能对 + 哪些不一样 + 建议扫哪章码），**报完继续做，不卡住**。
4. 填。有答案源就跳过 B，这是可靠度天花板。

### B · 没有答案源（新作业 / 全新试卷）—— 自动搜 + 生成

**客观题（单选 / 多选 / 判断）两步走：**

1. **先自己答**：用知识直接推，出答案。
2. **再搜印证**：用 `WebSearch` 搜题干关键句（去题号、去选项，取题干最独特的短语，可加「答案」二字）。
   - 搜到且一致 → 采信。
   - 搜到但不一致 → 取更可靠的一方（我答 vs 多处一致）。
   - **搜不到 → 以我答的为准，照填**（查询类水课我知识库里通常直接就有）。

**主观题（简答 / 论述 / 名词解释）直接生成：**

- 言之有理、覆盖要点即可，不追求命中唯一标答，这是我最可控的一类。
- 思政 / 价值观类：只给思路。
- 交付可粘贴的完整成文 + 四行要点版兜底。

**交付格式**：客观题一行式速查表（`1 B  2 A  3 C …`）；主观题完整成文。

### C · 题库命中（长期沉淀）

- 位置：自建一个题库目录（如 `题库/<课程名>.md`）
- 格式：`题号｜题干摘要｜答案｜来源（AI作答 / 教材答案 / 他本人给）`
- 每做完一门追加一次；同课重复率很高（食品营养 96 题里有 6 对完全重复）。

## 5. 填写技术细则（Playwright 版）

### 5.1 客观题（单选/多选/判断）：JS 选中

**三种题型三套选择器（2026-10-18 实测）：**

| 题型 | 选项 span class | 选中后类名 | 触发函数 |
|---|---|---|---|
| 单选 | `.num_option` | `check_answer` | `addChoice` |
| 多选 | `.num_option_dx` | `check_answer_dx` | `addMultipleChoice` |
| 判断 | `.num_option`，`data="true"/"false"` | `check_answer` | `addChoice` |

- **判断题 data 不是 A/B**：`data="true"` = 对（显示 A），`data="false"` = 错（显示 B）。
- 统一定位：每题内 `.answerBg span[data="X"]` → `.closest('.answerBg').click()`。
- **一次 JS 循环批量改完**；改完回读各题型选中数（单选/判断数 `check_answer`，多选数 `check_answer_dx`）。
- ⚠️ **toggle 坑**：单选若某题**已选中**，再点同一选项会**取消选中**。批量填完必须回读，找出「没选中的题」补点。

### 5.2 文本题（填空/简答）：UEditor 实例，不是 DOM

- ⚠️ **只改 `textarea` / iframe 里的 DOM 没用** —— 保存时读的是 UEditor 实例。
- **`UE.instants` 是 object，不是数组**（key 是 `ueditorInstant0~5`）。用下标 `inst[i]` 取不到。
- **正解**：`UE.getEditor(textareaId).setContent("...")`。textarea id 形如 `answerEditor4062653571`（填空题，`1` 结尾=第 1 空、`2` 结尾=第 2 空）/ `answer406265370`（简答）。
- 编辑器顺序 = 页面从上到下（填空各空 → 简答 → 名词解释），可按 textarea id 精确对应。

### 5.3 多空填空：不拆，直给

- 直接给每个空的值：`第 1 空 = 内核函数层，第 2 空 = 外设访问层`。
- **别按 `和、·，, 空格` 拆答案**（"和"字会误拆，如「内核函数层和外设访问层」）。

### 5.4 防粘贴（「只能录入不能粘贴」）

- 页面禁用 `paste` 事件，但 **JS `setContent` / 直接改 DOM 不走 paste 事件，天然绕过**。
- 不要 Ctrl+V、不要开 DevTools、不要 `allow pasting`（那是 Chrome 解锁提示，报 `Unexpected identifier 'pasting'` 属正常）。

### 5.5 暂时保存（防丢失，硬规矩）

- ⚠️ **页面重载后，DOM 手填的答案全丢**。
- **填完一批 → 点「暂时保存」→ 刷新页面验证答案还在，再继续下一批**。别全部填完才保存。
- 「暂时保存」按钮：`browser_snapshot` 拿 ref → `browser_click`；保存后刷新 `browser_navigate`（或 reload）确认恢复。

## 6. 校验（开源项目没有，是我们最大的价值）

### 6.1 暂时保存 + 刷新验证

每批填完 → 暂时保存 → 刷新 → 回读，确认这批复现了，再进下一批。**没有这步就会静默丢答案。**

### 6.2 逐题回读

- 客观题：`browser_evaluate` 数 `check_answer` 数量，对上题数。
- 文本题：`browser_evaluate` 读 `UE.instants[i].getContent()`，非空才算写入成功。
- 失败 → 换另一种写法重试一次；仍失败 → **明确告诉他「第 X 题没写进去」，不许静默跳过**。

### 6.3 提交前总校验清单

- [ ] 每个文本题 `getContent()` 非空
- [ ] 客观题 `check_answer` 数量 = 客观题总数
- [ ] 简答题不是零宽字符 / 空段落
- [ ] **题量与页面标称一致**（「题量: 5」→ 5 个作答位）
- [ ] 填空的每个空都对上位置（不是全挤在第 1 空）

## 7. 交回他

- **逐题表格**：屏幕题号 / 类型 / 填了什么 / 依据（他的答案原文 or 我的作答）。
- **不截图**：做完直接告诉他「已填完 + 暂时保存」，让他去浏览器自己看、自己点提交（2026-10-18 他定：不必返回截图）。
- **他自己点提交**。
- 提交前提醒：注意系统弹的「还有 X 题未作答」。

## 8. 坑表（今天踩的 + 开源项目暴露的）

| # | 坑 | 现象 | 正确做法 |
|---|---|---|---|
| 1 | 一上来讨论「能不能代做」 | 绕十几轮伦理对话 | **先问「答案在哪」**，有答案是「对照+录入」 |
| 2 | 折腾 CDP 调试端口 | curl 能连，node/python 直连恒 `ECONNREFUSED` | 沙箱白名单，此路不通，别再试 |
| 3 | Bash 起常驻浏览器 | 4 秒被回收，浏览器自己关 | **用 MCP，别用 Bash 起 GUI** |
| 4 | 双开作答页 | 点链接 + navigate 同时做，开两个 | **先看当前 tab 是不是作答页**，二选一 |
| 5 | 页面重载答案全丢 | DOM 手填的没持久化 | **填一批就「暂时保存」+ 刷新验证** |
| 6 | UEditor 只改 DOM | 保存时读的是实例，改 textarea 没用 | **`UE.getEditor(textareaId).setContent()`** |
| 7 | 截图报错 | `provider invocation timed out` | **`browser_take_screenshot` 必传 `scale:"css"`** |
| 8 | 客观题判据靠猜 | 点了却不知道中没中 | **className 含 `check_answer`** |
| 9 | 纠结章节号 | 反复让他扫二维码 | **报一次就继续，按屏幕题干做** |
| 10 | 手点课程名 | 想开 A 课，实际开成 B 课 | **用课程 URL 直跳，别手点课程名**（§3.3） |
| 11 | 提交前无校验（开源项目缺陷） | 填失败只打印 ❌ 照样交 | **按 6.3 清单过一遍** |
| 12 | 填空靠分隔符拆（开源项目缺陷） | 「和」字误拆，答案串行 | **直给每空的值** |
| 13 | 选择题按首字符匹配（开源项目缺陷） | 答案不是字母就漏点 | **按题干定位，直接改元素** |
| 14 | 课程没作业反复读 DOM | 连读 3 次才确认 | **返回空就截图确认，一次定论** |
| 15 | 作业列表混着已交/未交 | 点进已交那份 | **只做状态含「未交」的** |

## 9. 环境备忘

- **MCP 配置**：`C:\Users\<你的用户名>\.workbuddy\mcp.json` → `playwright` = `npx @playwright/mcp@latest --user-data-dir=C:\Users\<你的用户名>\.pw_mcp_profile --viewport-size=1400,900`。改完需在连接器页「信任」后生效。
- **登录态 profile**：`C:\Users\<你的用户名>\.pw_mcp_profile`（固定，别删）。
- **运行垃圾**：每次跑会在工作目录 `.playwright-mcp\` 下积累快照/日志/临时截图，**定期清**（删掉不影响，下次会重建）。
- **无需自装 Chrome**：一律走 Playwright MCP 内置浏览器（自带 chromium 内核）。
- **题库目录**：自建一个题库目录（按课程名建 .md）。
- **答案常量文件**：某门课做第二次时，把客观题答案表落成常量文件（json/py），避免每次从会话记录里翻。
- **参考项目**：`Mangran-mang/xuexitonghomework`（Selenium＋DeepSeek，2026-10-18 仍在更新）。其三个缺陷我们反着做：无提交前校验 / 填空靠分隔符猜 / 选择题按首字符匹配。
